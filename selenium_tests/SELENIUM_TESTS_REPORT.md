# DeepShield Selenium Test Work

## Overview

Created beginner-friendly Selenium and pytest tests for the DeepShield web
application. Existing application code was not modified.

The tests use:

- Python
- Selenium WebDriver
- pytest
- pytest-html
- Chrome
- `http://localhost:5000`

## Browser Fixture

[`conftest.py`](./conftest.py) provides:

- `BASE_URL = "http://localhost:5000"`
- A Chrome `driver` fixture
- Maximized browser startup
- Automatic browser cleanup
- Failure screenshots saved to `selenium_tests/screenshots/`

The localhost URL is intentional. It matches the frontend configuration:

```text
NEXT_PUBLIC_API_BASE=http://localhost:5000
```

This avoids the origin difference between `localhost` and `127.0.0.1`.

## Locators Found From the Real Frontend Code

The locators were taken from the actual React/Next.js components rather than
guessed.

### Upload file input

```css
input[type="file"]
```

The input has no stable `id` or `name`, so the type selector is used.

### Run analysis button

```xpath
//button[normalize-space()='Run analysis']
```

The button has no stable `id`; its visible text is stable in
`detect-workbench.tsx`.

### Verdict

The result component renders one of these exact labels:

```text
Likely authentic
Likely manipulated
Inconclusive
```

The tests wait for one of these visible text values.

### Confidence/score area

The result panel renders:

```text

```

The test checks for a percentage such as `67.4%` in the result text.

### Face crops

The crop gallery renders images with this observed selector:


The test asserts that at least one analysed face crop is displayed.

### Invalid-file error

The test locates the error paragraph containing:

## Test Cases

### TC1: Navigation and browser handling

Implemented in [`test_navigation.py`](./test_navigation.py).

The test:

1. Opens the home page.
2. Checks the page title.
3. Checks the current URL.
4. Opens `/detect/`.
5. Opens `/about/`.
6. Goes back.
7. Goes forward.
8. Refreshes the page.

Explicit URL waits are used after client-side navigation.

### TC2 and TC3: Upload and result

Implemented in [`test_upload_and_result.py`](./test_upload_and_result.py).

The tests:

1. Use the relative source path `selenium_tests/sample.mp4`.
2. Resolve it to an absolute path before Selenium `send_keys()`.
3. Upload through the real file input.
4. Click `Run analysis`.
5. Wait up to 120 seconds using `WebDriverWait` and
   `expected_conditions`.
6. Check the verdict.
7. Check the manipulation score percentage.
8. Check that face crops are displayed.
9. Print the analysis duration.

Selenium requires an absolute filesystem path for file upload, so the tests
keep the requested relative sample-video location but call `.resolve()` before
`send_keys()`.

### TC4: Invalid file

Implemented in [`test_invalid_file.py`](./test_invalid_file.py).

The test creates a temporary `selenium_tests/invalid.txt`, uploads it, checks
the real validation message, and removes the temporary file afterward.

### TC5: New tab

Implemented in [`test_new_tab.py`](./test_new_tab.py).

The test searches for a real `a[target="_blank"]` link. If one is added to the
application later, it will:

1. Save the original window handle.
2. Click the link.
3. Switch using `driver.window_handles`.
4. Assert the new URL.
5. Close the new tab.
6. Switch back to the original tab.

At present, the test skips because no such link exists.

### Waits demonstration

Implemented in [`test_waits_demo.py`](./test_waits_demo.py).

It demonstrates:

1. No wait - marked `xfail` because the asynchronous result is expected not to
   be ready immediately.
2. Implicit wait.
3. Explicit `WebDriverWait` with a 120-second timeout.

## Commands Used

Install dependencies:

```powershell
.\venv\Scripts\python.exe -m pip install selenium pytest pytest-html
```

Run the requested complete suite:

```powershell
.\venv\Scripts\python.exe -m pytest selenium_tests -v --html=selenium_tests/report.html --self-contained-html
```

Run only the verified non-analysis tests:

```powershell
.\venv\Scripts\python.exe -m pytest selenium_tests/test_navigation.py selenium_tests/test_invalid_file.py selenium_tests/test_new_tab.py -v
```

## Presentation Notes

For the university presentation, explain that:

- `driver.get()` opens a URL.
- `driver.back()` and `driver.forward()` operate browser history.
- `driver.refresh()` reloads the current page.
- `send_keys()` uploads a file directly to an HTML file input.
- An implicit wait affects element lookup calls globally.
- An explicit `WebDriverWait` waits for a specific condition.
- The no-wait test is intentionally marked `xfail` to demonstrate why waits
  are needed for asynchronous analysis.
- The app has no current new-tab link, so the window-handle demonstration is
  prepared but skipped until such a link exists.
